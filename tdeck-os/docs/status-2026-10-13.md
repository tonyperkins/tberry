# Status and next steps, 2026-10-13

A review of where tdeck-os stands, written after the first-boot setup, emoji picker and remote
debug tooling landed. Tickets live in `docs/backlog/`; this is the thinking behind what to pick next.

## Where it stands

Standalone MeshCore messenger: messages (direct and Public channel), signal test, nodes, offline map,
status, settings with PIN-protected advanced radio controls, first-boot setup, emoji (inline and
picker), lock screen that resumes the previous screen, screen timeout, sound effects. Debug builds
(`tdeck-remote`) can be driven and screenshotted over USB by `tools/remote.py`.

## Built but not proven in use

- GPS battery saving (TDOS-009): no meter, never measured.
- Pending-ACK expiry (issue 2) and own-name matching with emoji names (issue 4).
- Sent emoji in other clients, including that a heart arrives as an emoji and not a text glyph.
- Stability over days. LVGL's pool leaves about 71 KB free, and the emoji picker once exhausted it,
  so headroom is thin.

## Gaps for the real use case (a non-technical user far from the owner)

1. **No remote update path.** Updating needs USB and PlatformIO. Updating from a `firmware.bin` on
   the SD card would let a file be sent to the device's owner. Biggest practical gap.
2. **Only the Public channel.** A lot of mesh traffic is on hashtag channels (`#test`, `#austin`).
   Their key derives from the name, so joining one needs only a name box. Without it a standalone
   device cannot take part.
3. **No crash diagnostics.** Nothing records why a device rebooted. Show the reset reason in
   About and keep a short log on the card.

## Smaller items

- "Share my position" switch (default off) and range-test results on the map.
- Trackball left/right to move the cursor in the message box (not verified as wired).
- Sending reactions: blocked on how the 8-character code is derived (TDOS-008). Next step is a day
  or two of listening, then `tools/find_reaction_id.py` on `/tdos/idlog.csv`.
- A GitHub Actions build check; host tests for the parsers (issue 9); keyboard shortcuts (issue 8,
  tabled by the owner).
- Real screenshots in the README, taken with the remote tool.

## Suggested order

1. Commit the debug tooling and README, keep the debug build on the bench device while developing.
2. SD-card update, then hashtag channels, then reset-reason logging.
3. A short field test to confirm the unproven list above.

## Debug and release builds

Same source, one flag. `tdeck` is the release (no remote control compiled in); `tdeck-remote` adds
the serial control. About shows "debug" in the debug build, and `tools/release.sh` builds the release
and refuses to finish if debug code is in the image.

## Known issues (added later the same day)

- The T-Deck keyboard backlight does not light. Not investigated yet.
- Over-the-air update is verified on the bench over HTTP (install, bad signature, wrong checksum,
  up to date). The HTTPS path against GitHub releases is untested until a release exists.
